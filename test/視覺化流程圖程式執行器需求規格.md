# 視覺化流程圖程式執行器需求規格

## 1. 文件目的

本文件定義 PyJudge 視覺化流程圖程式執行器的產品目標、核心功能、技術原則、驗收標準與後續擴充方向，供開發 Agent 進行架構設計與實作。

本功能採用「流程圖優先」的設計。學生以拖曳節點、拉取連線的方式建立流程圖，系統負責驗證與安全執行，並透過動畫、變數狀態及輸出結果呈現每一個執行步驟。

```text
學生繪製流程圖
    ↓
系統驗證流程圖
    ↓
安全執行流程圖
    ↓
產生執行軌跡
    ↓
播放視覺化動畫
```

第一階段不處理任意 Python 程式碼自動轉換成流程圖。

## 2. 產品目標

### 2.1 核心目標

- 提供直覺且流暢的流程圖繪製體驗。
- 讓學生可以直接執行自己建立的流程圖。
- 視覺化呈現控制流程、條件結果與變數變化。
- 支援播放、暫停、逐步執行、回到上一步及速度調整。
- 協助學生理解條件判斷、迴圈及基礎演算法。
- 建立安全、可測試、可擴充的流程圖執行架構。

### 2.2 設計原則

- 教學理解優先於功能數量。
- 操作流暢度是核心需求，不是後期最佳化項目。
- 畫布、執行引擎與動畫播放器必須解耦。
- 不直接執行未受限制的使用者程式碼。
- 第一版先建立可靠的基礎語意，再逐步增加語法與節點。
- 優先整合並重用現有 PyJudge 的架構、元件與視覺規範。

## 3. 目標使用者

- 剛開始學習程式設計的學生。
- 需要示範程式執行流程的教師。
- 正在學習條件判斷、迴圈與基礎演算法的使用者。

## 4. 核心使用流程

1. 學生進入流程圖編輯頁面。
2. 從工具列拖曳節點至畫布。
3. 從節點連接點拖曳並建立連線。
4. 編輯節點內的輸入、輸出、變數或運算式。
5. 系統即時提示結構或語法錯誤。
6. 學生輸入測試資料並執行流程圖。
7. 系統高亮目前節點及執行路徑。
8. 學生觀察條件結果、變數變化與輸出內容。
9. 學生可暫停、逐步前進、返回上一步或調整速度。
10. 學生修改流程圖後重新驗證與執行。

## 5. 第一階段功能需求

以下項目均為第一階段必要功能，優先級為 P0。

### 5.1 流程圖畫布

畫布需要支援：

- 從工具列拖曳新增節點。
- 自由移動節點。
- 從節點連接點拖曳建立連線。
- 顯示可接受連線的目標。
- 選取節點或連線。
- 刪除節點或連線。
- 複製及貼上節點。
- 多選及框選。
- 復原與重做。
- 畫布縮放及平移。
- 自動置中及適應畫面。
- 儲存及載入流程圖。
- 防止明顯不合法的連線。
- 在流程圖修改後將既有執行結果標記為失效。

### 5.2 基礎節點

第一版至少支援以下節點：

| 節點 | 用途 | 主要設定 |
| --- | --- | --- |
| 開始 Start | 流程進入點 | 無 |
| 結束 End | 流程結束點 | 無 |
| 輸入 Input | 取得使用者輸入 | 提示文字、目標變數 |
| 輸出 Output | 顯示文字或運算結果 | 輸出運算式 |
| 處理 Process | 宣告、指定或更新變數 | 指定運算式 |
| 判斷 Decision | 根據條件選擇分支 | 布林運算式 |

條件節點必須有明確的 `True` 與 `False` 出口。

每個節點至少包含：

- 唯一 ID。
- 節點類型。
- 顯示標題。
- 可編輯內容。
- 輸入與輸出連接點。
- 畫布位置。
- 執行狀態。
- 驗證狀態及錯誤訊息。

### 5.3 第一版語言能力

第一版應採用受限制的教學語言，至少支援：

- 數字、字串及布林值。
- 變數宣告或首次指定。
- 變數重新指定。
- 四則運算及餘數運算。
- 括號及運算優先順序。
- 大於、小於、等於及不等於等比較運算。
- 基本邏輯運算。
- 使用者輸入。
- 輸出文字、變數或運算結果。
- 條件分支。
- 以流程圖回邊表達的迴圈。

運算式範例：

```text
x = 10
sum = sum + x
x > 5
x % 2 == 0
name + "，你好"
```

系統不可直接使用不受限制的 `eval`，也不可直接執行使用者提供的原生 Python 或 JavaScript。運算式必須經過安全的 Parser、AST 或受限解譯器處理。

### 5.4 流程圖驗證

執行前至少檢查：

- 是否有且只有一個開始節點。
- 是否存在結束節點。
- 開始節點是否連接下一個節點。
- 必要節點是否缺少輸入或輸出連線。
- 條件節點是否具有 `True` 與 `False` 分支。
- 是否存在無法從開始節點抵達的節點。
- 運算式語法是否合法。
- 變數名稱是否合法。
- 是否引用尚未定義的變數。
- 是否出現不允許的節點連接方式。

錯誤必須直接呈現在相關節點或連線上，並提供學生能理解的訊息，不得只顯示內部錯誤或堆疊資訊。

可能的無限迴圈不一定能在靜態階段完整判斷，因此執行階段還需要步數與時間限制。

### 5.5 執行引擎

執行架構應分為以下層次：

```text
Flowchart Graph
      ↓
Validation
      ↓
Intermediate Representation
      ↓
Sandboxed Interpreter
      ↓
Execution Trace
      ↓
Animation Player
```

執行引擎每完成一步，應產生一筆不可變的執行事件。建議格式如下：

```json
{
  "step": 8,
  "nodeId": "decision-2",
  "type": "condition",
  "expression": "score >= 60",
  "result": true,
  "variablesBefore": {
    "score": 85
  },
  "variablesAfter": {
    "score": 85
  },
  "nextNodeId": "output-1"
}
```

計算速度與動畫速度不得直接綁定。執行引擎負責計算及產生軌跡，動畫播放器負責依指定速度呈現事件。

執行引擎必須具備：

- 最大執行步數限制。
- 最大執行時間限制。
- 無限迴圈保護。
- 執行取消能力。
- 清楚的成功、停止及錯誤狀態。
- 可測試的確定性輸出。

### 5.6 執行視覺化

執行時至少呈現：

- 目前正在執行的節點。
- 即將行走或剛走過的連線。
- 已執行過的路徑。
- 條件運算式及判斷結果。
- 節點執行前後的變數變化。
- 等待使用者輸入的狀態。
- 輸出結果。
- 執行完成、停止或錯誤狀態。

節點及連線至少需要區分以下狀態：

- 未執行。
- 目前執行。
- 已執行。
- 暫停。
- 等待輸入。
- 執行錯誤。

動畫需清楚、平順且容易追蹤。視覺效果的主要目的為解釋執行流程，不應因過度裝飾而干擾閱讀。

### 5.7 執行控制列

至少提供：

- 執行。
- 暫停及繼續。
- 下一步。
- 上一步。
- 停止。
- 重新開始。
- 播放速度調整。
- 目前步驟及總步驟顯示。

建議速度選項：

```text
0.25× / 0.5× / 1× / 2× / 4×
```

切換速度不得重新執行流程圖或改變計算結果。返回上一步應透過執行軌跡恢復畫面及變數狀態，不需要反向執行程式。

### 5.8 變數與輸出面板

畫面右側或可收合面板至少顯示：

- 目前變數名稱。
- 變數類型。
- 目前值。
- 上一步的值。
- 本步驟發生變化的變數。
- 輸入紀錄。
- 輸出紀錄。
- 目前條件及判斷結果。

建議提供簡易變數時間軸：

| 步驟 | 節點 | i | sum |
| ---: | --- | ---: | ---: |
| 1 | 初始化 | 1 | 0 |
| 2 | 指定 | 2 | 1 |
| 3 | 指定 | 3 | 3 |

## 6. 操作體驗與效能要求

流暢操作體驗屬於核心驗收項目。

### 6.1 體驗目標

- 一般桌面環境的拖曳與縮放體驗應接近 60 FPS。
- 節點拖曳必須即時跟手，不出現明顯延遲或跳動。
- 拉線時即時顯示可接受連線的節點或接點。
- 動畫播放期間仍可平移與縮放畫布。
- 變數面板更新不得造成整個畫布重新渲染。
- 約 100 至 200 個節點時仍能正常編輯與瀏覽。
- 自動儲存不得阻塞拖曳、輸入或動畫播放。

### 6.2 實作注意事項

- 編輯狀態、執行狀態與播放器狀態應分離。
- 避免每次拖曳都序列化完整流程圖。
- 避免每個執行步驟都重新渲染全部節點。
- 避免以大量獨立 `setTimeout` 管理動畫。
- 避免在每次游標移動時執行完整流程圖驗證。
- 大量執行事件應考慮分段保存、虛擬化或事件壓縮。
- 動畫優先使用適合瀏覽器合成的 CSS 屬性。
- 高速播放時應限制昂貴 UI 更新的頻率，但不可遺失最終狀態。

## 7. 建議介面配置

第一版以桌面版為優先：

```text
┌──────────┬─────────────────────────┬──────────────┐
│ 節點工具列 │                         │ 變數與輸出面板 │
│          │       流程圖畫布         │              │
│ Start    │                         │ Variables    │
│ Input    │                         │ Output       │
│ Process  │                         │ Conditions   │
│ Decision │                         │              │
└──────────┴─────────────────────────┴──────────────┘
┌───────────────────────────────────────────────────┐
│ 執行｜暫停｜上一步｜下一步｜停止｜速度｜執行進度       │
└───────────────────────────────────────────────────┘
```

簡單內容可直接在節點內快速編輯；較複雜的設定可以透過雙擊節點或右側屬性面板處理。

## 8. 建議資料格式

流程圖資料格式必須可版本化，並與畫布顯示套件解耦。

```json
{
  "version": 1,
  "title": "判斷奇偶數",
  "nodes": [
    {
      "id": "start-1",
      "type": "start",
      "position": {
        "x": 120,
        "y": 80
      },
      "data": {}
    },
    {
      "id": "input-1",
      "type": "input",
      "position": {
        "x": 120,
        "y": 180
      },
      "data": {
        "variable": "number",
        "prompt": "請輸入整數"
      }
    }
  ],
  "edges": [
    {
      "id": "edge-1",
      "source": "start-1",
      "target": "input-1",
      "branch": null
    }
  ],
  "viewport": {
    "x": 0,
    "y": 0,
    "zoom": 1
  }
}
```

資料格式不可過度依賴特定畫布套件的內部結構，以保留未來更換前端工具的可能性。

## 9. 第一階段驗收案例

以下案例皆應能正確建立、儲存、重新載入及執行：

1. 輸入姓名並輸出問候語。
2. 判斷整數是奇數或偶數。
3. 判斷成績是否及格。
4. 找出兩個數字中的較大值。
5. 計算 1 到 n 的總和。
6. 使用迴圈輸出 1 到 10。
7. 建立無限迴圈後，由系統在限制內安全中止。
8. 使用未定義變數後，在對應節點顯示清楚錯誤。
9. 建立缺少 `False` 分支的條件節點後，系統阻止執行。
10. 執行中可以暫停、逐步前進、返回上一步及切換速度。
11. 流程圖修改後，舊的執行軌跡不會繼續套用於新流程圖。
12. 儲存並重新載入後，節點、連線、設定及畫布位置保持一致。

## 10. 測試與品質要求

### 10.1 單元測試

- 流程圖結構驗證。
- 運算式 Parser 及語意驗證。
- 變數讀取與指定。
- 條件分支選擇。
- 迴圈及最大步數限制。
- 執行事件產生。
- 錯誤事件與中止行為。

### 10.2 整合測試

- 拖曳節點並建立連線。
- 編輯節點後正確更新資料。
- 執行控制列與播放器互動。
- 變數面板與目前執行步驟同步。
- 儲存、載入及版本處理。
- 修改流程圖後清除或失效舊執行狀態。

### 10.3 人工驗證

- 節點拖曳、拉線、縮放及平移是否流暢。
- 動畫播放期間是否仍可操作畫布。
- 錯誤訊息是否適合初學者理解。
- 高速播放時是否仍呈現正確最終狀態。
- 瀏覽器控制台是否存在持續性錯誤或警告。

## 11. 後續功能 P1

第一版穩定後再評估：

- 陣列及陣列長條圖視覺化。
- `for` 型迴圈節點。
- 函式定義與呼叫。
- 呼叫堆疊視覺化。
- 遞迴。
- 中斷點。
- 執行到指定節點。
- 畫布小地圖。
- 自動排列流程圖。
- 範例流程圖及教學引導。
- 教師鎖定部分節點。
- 題目起始模板。
- 學生提交與評分。
- 流程圖產生 Python 程式碼。
- 流程圖與程式碼同步高亮。
- 排序及搜尋演算法專用視覺化。
- 多組測試資料批次執行。
- 分享及匯出流程圖。

## 12. 第一階段非目標

以下功能不納入第一階段：

- 任意 Python 程式碼自動轉換成流程圖。
- 執行未受限制的 Python 或 JavaScript。
- 多人即時協作。
- 完整 IDE 或完整除錯器。
- 完整 Python 語法。
- 複雜物件導向能力。
- 手機版完整流程圖編輯。
- 一次加入大量低使用率節點類型。

## 13. 開發 Agent 執行要求

開始實作前，開發 Agent 必須：

1. 檢查現有 PyJudge 的專案架構、技術棧及 UI 規範。
2. 找出適合整合的頁面、路由、狀態管理及資料層。
3. 優先重用現有元件及樣式。
4. 先提出簡短架構方案及預計變更的檔案範圍。
5. 將功能拆分成可獨立驗證的小階段。
6. 保持現有功能與資料相容，不破壞既有 PyJudge 行為。

完成實作後，開發 Agent 必須：

- 執行既有測試、型別檢查及正式建置。
- 為驗證器及執行引擎補充單元測試。
- 為主要畫布互動補充整合測試。
- 手動驗證拖曳、拉線、縮放與執行動畫。
- 確認瀏覽器控制台沒有持續性錯誤。
- 說明新增檔案、架構決策、已知限制及後續擴充方式。

## 14. 開發任務摘要

> 請先檢查現有 PyJudge 專案，設計並實作一個桌面優先、操作流暢的拖曳式流程圖程式執行器。第一版以流程圖建立與安全執行為核心，支援開始、結束、輸入、輸出、指定與條件節點，提供流程驗證、變數觀察、執行軌跡、單步控制、回放及速度調整。畫布、執行引擎和動畫播放器必須解耦，禁止直接執行不受限制的使用者程式碼，並以可測試、可擴充且不破壞既有功能的方式整合至目前專案。
