# SkillLab 未來發展藍圖

## 一、願景

SkillLab 不只是一個 Python 線上判題網站，而是一座跨年齡、跨工具、能連接真實專題的能力實驗室。平台希望讓國小學生、大學生與社會人士，都能依自己的起點進入合適的學習路線，逐步經歷：

> 看懂問題 → 拆解步驟 → 動手建構 → 執行驗證 → 修正錯誤 → 完成作品

長期目標是把目前的程式自學與驗證功能，發展成大型學習與專題生態系中的一個核心子項目，並與機械、電子、控制、感測及自動化等機電實作內容串接。

## 二、產品定位

SkillLab 的核心價值有三個：

1. **降低第一次接觸程式的門檻**：以 Scratch、Blockly 等積木工具建立邏輯，再平順轉換到文字程式。
2. **提供可持續成長的練習系統**：透過分級題庫、即時執行、自動驗證、提示與學習紀錄，支援長期自學。
3. **讓程式能力走出螢幕**：將題目能力連接到感測器、致動器、控制系統與跨領域專題，完成可展示、可驗證的作品。

平台不以年齡直接限制內容，而是以「先備能力、學習目標與表達方式」安排入口。相同概念可以有兒童情境版、學術版與職場應用版，讓不同年齡的學習者共享底層能力架構。

## 三、服務對象與學習入口

| 學習族群 | 主要需求 | 建議入口 | 代表成果 |
|---|---|---|---|
| 國小中低年級 | 建立順序、事件、條件與重複概念 | Scratch／圖像化任務 | 動畫、互動故事、小遊戲 |
| 國小高年級 | 從積木邏輯過渡到簡短程式 | Blockly＋Python 對照 | 小工具、基礎自動判題 |
| 國高中生 | 建立完整程式基礎與解題能力 | Python 課程＋分級 Judge | 演算法題、資料處理、小專題 |
| 大專學生 | 補強程式、工程整合與專題實作 | 進階題庫＋專題任務 | API、資料分析、控制與機電整合 |
| 社會人士 | 依目標快速補足實用能力 | 主題式路線＋診斷練習 | 自動化工具、工作流程、作品集 |

為避免內容被年齡標籤綁住，介面可優先詢問「你想做什麼」與「目前熟悉什麼」，再推薦適合的起點。學習者也可以自由切換路線，而不是被固定在單一等級。

## 四、學習內容架構

### 4.1 共通能力主軸

所有工具與課程共用同一套能力地圖：

- 程序與事件：順序、輸入輸出、事件觸發
- 資料與運算：變數、型別、算術、字串、集合
- 邏輯與流程：比較、條件、迴圈、狀態
- 問題解決：拆解、模式辨識、演算法、測試與除錯
- 軟體實作：函式、模組、資料處理、介面與協作
- 系統整合：感測、控制、通訊、自動化與專題驗證

### 4.2 多工具學習階梯

```text
Scratch 情境探索
        ↓
Blockly 結構化積木
        ↓
積木／Python 並排對照
        ↓
Python 編寫與自動評測
        ↓
演算法、資料與應用題庫
        ↓
模擬器、硬體與機電專題
```

這條階梯不是單向限制。初學者可以從圖像化工具開始；已有經驗的使用者可直接進入 Python、題庫或專題。每一層都應保留「執行、觀察、驗證、修正」的共同學習節奏。

### 4.3 題庫規劃

題庫將從目前的 Python 基礎題，擴充成可依多個維度篩選的內容系統：

- 難度：啟蒙、基礎、進階、挑戰、專題
- 能力：輸入輸出、條件、迴圈、函式、資料結構、演算法、除錯
- 工具：Scratch、Blockly、Python，以及未來新增的語言或硬體環境
- 情境：生活應用、數學、遊戲、資料、科學、機電與自動化
- 學習模式：跟做、填空、除錯、獨立解題、開放式專題
- 先備關係：每題標示需要先掌握的概念與可銜接的下一步

同一個學習目標可設計多種表達版本。例如「條件判斷」可以是國小的紅綠燈積木、國高中的成績分類程式，以及成人的資料清理規則，但三者都對應相同的能力節點。

## 五、平台功能藍圖

### 學習體驗

- 起點診斷與學習路線推薦
- 分齡但不設限的內容呈現方式
- Scratch、Blockly 與 Python 的概念對照
- 可逐步開啟的提示、範例追蹤與錯誤說明
- 即時執行、自動測試與結果回饋
- 學習進度、概念熟練度與作品歷程
- 無障礙、行動裝置與低年齡操作需求

### 教學與內容管理

- 題目、測資、提示、解答與能力標籤分離管理
- 同題多版本及多工具對應
- 教師建立班級、指派路線與查看常見錯誤
- 題目版本控管、審題流程與品質檢查
- 開放式專題的規格、里程碑、紀錄與評量規準

### 評量與驗證

- 客觀題採自動判分與多組隱藏測資
- 積木題驗證輸出結果，也檢查必要的邏輯結構
- 專題採「功能測試＋過程證據＋成果展示」的多元評量
- 回饋重點從單純對錯，逐步延伸到可讀性、效率、測試思維與系統可靠度

## 六、與機電專題及大型項目的整合

SkillLab 在大型項目中負責「能力養成、練習驗證與專題前置訓練」。當學習者具備基礎能力後，可進入跨域專題模組：

1. **虛擬模擬**：先在網頁中操作虛擬感測器、馬達、燈號與控制流程。
2. **硬體入門**：連接 micro:bit、Arduino、Raspberry Pi 或其他控制板，完成單一元件任務。
3. **系統整合**：組合感測、致動、資料記錄、通訊與控制邏輯。
4. **真實專題**：以需求、限制、測試標準及成果展示完成完整作品。

可發展的專題路線包括：

- 智慧停車與交通控制
- 環境監測與資料儀表板
- 自動澆灌與智慧農業
- 機械手臂與移動載具
- 節能、警報與居家自動化
- 生產線模擬、設備狀態與預防維護

未來大型平台可共用帳號、能力地圖、學習紀錄與作品集；SkillLab 則保持模組化，透過清楚的資料介面輸出學習進度、題目結果、專題里程碑及能力證據。

## 七、階段性發展路線

### 階段 1：穩固現有核心

- 完成 SkillLab 品牌與定位調整
- 擴充 Python 初、中、高階講義與分級題庫
- 建立一致的題目格式、標籤、測資與審題規範
- 強化進度保存、錯誤回饋與行動裝置體驗

### 階段 2：導入積木程式

- 加入 Scratch 學習內容與作品任務
- 整合 Blockly 編輯器與執行／驗證流程
- 建立積木與 Python 並排、切換或轉譯體驗
- 讓同一能力節點能由不同工具完成

### 階段 3：建立跨年齡學習系統

- 上線起點診斷、推薦路線與個人學習地圖
- 建立兒童、青少年、大專與成人的情境版本
- 增加教師／導師端的班級、指派及學習分析功能
- 累積作品集、成就與能力證據

### 階段 4：連接專題與硬體

- 建立網頁模擬器與硬體抽象介面
- 導入感測器、控制板及機電任務包
- 建立專題模板、里程碑、測試規格與評量規準
- 與大型項目的帳號、資料與專題管理模組整合

### 階段 5：形成可擴充生態系

- 開放教師與合作夥伴建立課程、題組及專題包
- 建立內容審核、版本管理與發布機制
- 支援更多語言、裝置與產業情境
- 以匿名化學習資料持續改善路線與回饋品質

## 八、技術演進原則

- **先定義能力與內容資料，再綁定工具**：避免題庫只能服務單一語言。
- **編輯器、執行器、評測器分離**：讓 Scratch、Blockly、Python 與硬體模組可替換或並存。
- **保留離線與低設備門檻**：基礎學習盡量能在一般瀏覽器完成。
- **建立安全執行邊界**：程式碼執行、帳號資料及硬體連線需各自隔離與授權。
- **以 API 串接大型項目**：身份、進度、能力與作品資料使用穩定介面交換。
- **內容版本化**：題目、測資與課程更新後仍可追溯學習紀錄。
- **保護未成年使用者**：預設採最少資料收集、清楚的監護與教師權限，以及可理解的隱私說明。

## 九、成效指標

SkillLab 的成果不只看完成題數，也觀察學習者是否真正具備遷移與實作能力：

- 能否獨立完成下一個同概念題目
- 是否能在提示逐步減少後仍完成任務
- 能否閱讀錯誤訊息並有效修正
- 積木轉文字程式的完成率與卡點
- 不同背景使用者的持續學習與回訪情況
- 從基礎題進入專題、完成里程碑與作品的比例
- 專題能否通過功能、可靠度與展示標準

## 十、近期優先事項

1. 先將現有 Python 內容依能力節點、難度與先備概念重新標記。
2. 定義跨 Scratch、Blockly、Python 共用的題目與學習紀錄資料模型。
3. 選擇一個基礎概念製作「積木 → Python → 自動評測」的最小可行範例。
4. 選擇一個機電主題製作從模擬到硬體的示範專題。
5. 以實際學習者測試入口、提示、錯誤回饋與跨工具轉換是否順暢。

這份藍圖是 SkillLab 後續功能、內容與整合決策的共同方向。每一階段都應先以小規模可驗證成果測試，再依使用者回饋與大型項目的整合需求逐步擴充。
